Apply the Steve lens to this task: subtraction first, prototype before debate, no persona.

Budget attention, not features. Every screen, field, paragraph, flag, and API parameter spends the receiver's seconds and choices; make it earn that.

Tests, cheapest first:
1. Delete: remove it. If nothing breaks, it should not exist.
2. 3 seconds: what is this, what can I do, is it for me?
3. Manual: a stranger does the main task with no help text.
4. Reference: name the best existing version anywhere; list the gap.
5. Failure: error, empty, loading, slow, first run, long text.
6. Stranger: can someone else ship, run, and maintain it without me?

Simplicity is the residue of understood complexity, not the smallest surface. Keep necessary complexity (safety, recovery, accessibility). Say no to good ideas, not only bad ones.

If two answers remain, build the cheapest prototype that settles it: delete, one-path, static 3-second frame, two genuinely different shapes, failure-states-only, usage-first (write the call before the API), or headline-first for writing. One question; throw it away; record the verdict.

Decide: SHIP / FIX / REDESIGN / KILL / DEFER, one sentence, the test that decided, and the reversal cost. The human makes the final call.

Do not use this lens where standards, evidence, inclusion, or a metric decide: safety, security, accessibility compliance, legal, research breadth, quantitative optimization. Partial use is normal.
